## Declared divergences / native mappings

1. **`requestedBy`** — upstream embeds a full `ActorIdentity`. OStag records
   the compact `{platform, actorId, handle?}` `PrincipalRef`. Intake
   (`task.created`) events do not carry a human requester, so shadow capture
   attributes the instance's system principal:
   `{platform: "ostag", actorId: "instance:<instance_id>"}`.
2. **`policySnapshotId`** — upstream points at a versioned
   `PolicySnapshotProvenance` store. OStag has no versioned policy store yet;
   the capture records `ostag:<instance_id>:unversioned`, a **synthetic,
   non-resolving placeholder** — it does not reference any stored policy
   record, and nothing should attempt to dereference it. Recording a real
   provenance id requires a future versioned policy store; until then no
   provenance claim is being made.
3. **Timestamp comparison** — all timestamps are UTC-only (Z or +00:00;
   non-zero offsets rejected), and the expiry/revocation invariants compare
   **parsed instants**, never raw strings (valid UTC forms are not lexically
   equivalent — Phase 2 review lesson).
4. **`permissions` at capture are empty** — per-task capabilities travel on
   `instance.heartbeat` events in OStag, not on task events (the model
   rejects `per_task_capabilities` on task events). The shadow snapshot
   records only what the intake event itself proves. The
   `PermissionGrantRef` wire shape (`scope`, `reason`, `expiresAt`) is kept
   so richer capture can land later without a schema change; `scope` is a
   free string (upstream binds it to `PermissionScope`).
5. **`ostagBinding` (native extension)** — carries the existing precise
   routing identity (`instanceId`, optional `runtimeId`/`sessionId`/
   `turnId`/`sessionVersion`), mapping upstream `runner ↔ device/runtime
   host` and `executor ↔ agent adapter`. Intake-time capture fills only
   `instanceId`; session/turn fields are populated only when a real value
   exists.
6. **`agentPrincipal.kind` mapping** — agents shipped by OStag adapters
   (`codex`, `claude`, `claude-code`, `gemini`, `cursor`) map to
   `provider_agent`; any other declared agent maps to `custom`.
   `opentag_agent` is accepted on the wire but never produced by capture.
7. **Redaction boundary** — `redacted_view()` omits `brokerRef` and grant
   `reason` strings entirely (they never reach a board/API surface) and adds
   `contentDigest` so a viewer can verify integrity without seeing the full
   record.

## Shadow-mode guarantees (routing untouched)

- The capture hook is **constructor-injected and optional** on `Projector`,
  fires strictly **after** the projection transaction commits, and is
  wrapped in `try/except` — a capture failure can never change what
  `apply()` stores, buffers, or returns
  (`test_capture_failure_never_breaks_projection`).
- Nothing in `ostag/copilot_relay/` or any admission/candidate/route/
  fallback path imports or reads `access_snapshot*` — snapshots are
  write-at-intake, read-only via identity-scoped views.
- **Projection-equivalence proof**:
  `test_hooked_projection_is_equivalent_to_unhooked` replays an event corpus
  (in-order, gap-buffered, drained, duplicate, non-created) through a hooked
  and an unhooked projector and asserts identical `ApplyResult`s and
  row-for-row identical `events` / `tasks` / `pending_events` / `instances`
  table contents (logical equality of the projected state, not file-level
  bytes or timing).
- The Phase 0 dual-device acceptance fixture still reports
  `status=passed … crossed_routes=0` (run in this phase's verification).

## Capture durability (reconciliation)

The hook is deliberately best-effort, so a capture exception — or a crash
between the projection commit and the hook — would otherwise lose the
snapshot forever (the event replay is classified as a duplicate and the hook
never fires again). `AccessSnapshotStore.reconcile()` closes that gap: it
re-derives snapshots from the durable `events` table (every **projected**
`task.created` event must have a snapshot row; events still buffered in
`pending_events` are skipped so capture stays keyed to projection), and it
is idempotent. The server runs it best-effort at startup. Covered by
`test_reconcile_recovers_capture_lost_to_hook_failure`,
`test_reconcile_recovers_after_restart_without_hook`,
`test_reconcile_skips_buffered_unprojected_events`, and
`test_reconcile_scoped_to_instance`. Reconciliation decodes every
`task.created` event on each run — acceptable at shadow-phase volumes; an
anti-join on a denormalized task-id column is the known optimization if
volume grows.

## Persistence & rollback

- Migration v22 is additive-only; `test_migration_v22_is_additive_from_v21_fixture`
  proves a v21 database opens, keeps its rows, and gains the table.
- Rollback = downgrading code; the extra table is inert to older code
  (nothing reads it), consistent with the four-layer persistence decision in
  the baseline (§6.5).

## Authorization

Read surfaces reuse the existing boundary (baseline §6.3 idiom, same as the
Phase 2 boards): `personal_views` only queries the principal's own bound
instances; `admin_views` requires a bound global owner
(`SchemaError permission_denied` otherwise). Constructing the store without
an `IdentityStore` denies all view access rather than defaulting open.

`AccessSnapshotStore.get()` is an **internal, unredacted** accessor (it
returns broker refs and grant reasons and is not identity-gated) used by
capture/reconcile/tests. It is not exposed over HTTP or any board surface,
and must not be; external consumers go through the gated, redacted views.
