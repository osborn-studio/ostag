## 6. Recorded compatibility decisions (handoff §5.2 / §0.3 — resolved, not silent)

1. **Multiple run results:** OStag today has **no task↔run one-to-many**: `work_monitor/reporter.py:388` sets `task_id = run_id`; `osstack_references` PK retains only the latest attempt. Upstream `execution_compat`'s "any successful run satisfies" therefore **degenerates to N=1 and is exactly equivalent to current OStag behavior**. Decision: `workThreadId ↔ task_id (== run_id)`; the Phase 1 evaluator accepts `runResults: list` (N≥1-capable, matching upstream) but current integration always supplies ≤1. No existing behavior changes; no stop required. Future multi-attempt work may populate N>1 without evaluator changes.
2. **`crossed_routes` provenance:** the acceptance value is **authored in fixtures** (`tests/fixtures/multi-device/*.json`), validated — not computed — by `scripts/multi_device_copilot_acceptance.py`; live measurement is a manual operator procedure (`docs/operations/copilot-relay.md`). The deterministic gate for this upgrade is therefore *"fixture acceptance passes with `crossed_routes=0`"*, plus the guardrail that no phase touches routing code paths in a way that would invalidate the manual procedure. Recorded honestly; a computed metric is future work (candidate for Phase 6 doc).
3. **"Personal board" mapping:** the handoff's employee/admin language maps onto OStag's real scoping: `personal` = principal-bound device scope (`status_board._allowed`), `admin/team` = global-owner scope. Phase 2 will build `WorkLoopView` behind this **existing** authorization boundary rather than inventing a new employee model.
4. **`assessedBy` attribution:** OStag will emit `"ostag" | "human"` (native divergence from upstream `"opentag" | "human"`), declared in the Phase 1 mapping note + compatibility test, per handoff §5.1.
5. **Persistence strategy for Phase 1:** append-only `CompletionAssessment` + evidence/waiver records go into **SQLite via `MonitorStore.MIGRATIONS`** (additive `user_version` bump) — it already provides transactions for the optimistic-concurrency `recorded|duplicate|conflict` append and a tested migration idiom. The JSONL run ledger keeps mirroring terminal events for audit continuity.
