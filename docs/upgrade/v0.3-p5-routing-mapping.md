## What was deliberately NOT ported (handoff §9 constraint)

Upstream Phase 3 also added an **authoritative placement selector**. None of
it is ported. The existing OStag router (`CopilotRelayService`) makes every
decision **unchanged**; `RouteExplainer` wraps it, lets the real call happen
byte-for-byte, and derives the explanation **strictly afterwards** from the
actual outcome plus plain SQLite reads. The explainer **never calls the
relay policy** (a stateful `can_access` provider observes the same number of
lookups with or without explanations — proven by
`test_explainer_makes_no_extra_policy_calls`); eligibility is derived from
what the router actually did (it routed ⇒ eligible; it rejected with
access/terminal errors ⇒ ineligible with that reason). No code path reads a
stored `RoutingDecision` during routing — explanations are persist/display
only.

## Production wiring

`CopilotFeishuController` takes an optional `route_explainer`; the server
constructs it with `RoutingDecisionStore(monitor_store, identities)`. Every
production routing decision is explained: text messages, quoted decision
answers (incl. card callbacks), snapshot requests, and proposal
confirmations. Decision ids are deterministic per attempt
(`rd_{event_id}` / `rd_callback_{callback_id}` with per-path suffixes).
Explicit task selection (`select_session`) is a human choice, not a routing
decision, and is declared out of scope. **Recording is best-effort** (the
Phase 3 shadow-hook contract): a persistence failure or id conflict can
never change the routing result or mask a router exception — proven by
`test_recording_failure_never_changes_routing` and
`test_recording_conflict_never_masks_router_outcome`.

## Ported type semantics (kept)

| Upstream | OStag |
| --- | --- |
| `RoutingCandidateReason { code, message }`, both min(1) | same |
| `RoutingCandidate { runnerId, executorId, eligible, reasons.min(1), locality?, readiness?, capacity{active≥0, limit≥1}? }` | same; locality/readiness enums kept verbatim (`local\|private\|hosted`; `ready\|stale\|draining\|at_capacity`) |
| `RoutingDecision { id, runId, policySnapshotId?, accessProfileSnapshotId?, candidates[], selected?, reasonCode, reason, decidedAt }` | same |
| superRefine: a decision may select only an **eligible** candidate | enforced in `__post_init__` |
| candidates array has no minimum (may be empty) | same (a failed attempt with no discoverable session has zero candidates) |

Validation follows the Phase 3/4 strictness standard: typed scalars,
model-instance nesting, required wire keys, strict UTC grammar, unknown-key
rejection, no `AttributeError` escapes.

## Native mappings (declared)

1. **`runnerId` = `"{instance_id}/{runtime_id}"`** — runner ↔ device/runtime
   host, consistent with the Phase 3 identity mapping.
2. **`executorId` = relay `session_id`** — the executable unit OStag routes
   to. (The agent adapter id is visible via the session, not duplicated in
   the explanation.) `selected` therefore encodes exactly the actual route:
   the routed envelope's `(instance_id, runtime_id, session_id)` binding.
3. **`runId`** = the routed session's `run_id`; for attempts that failed
   before any session was found, the decision id (attempt id) — declared
   fallback, since upstream requires a non-empty `runId`.
4. **`policySnapshotId`** = the Phase 3 synthetic placeholder
   `ostag:<instance_id>:unversioned` when a session was found; absent
   otherwise. `accessProfileSnapshotId` is populated only when a real
   snapshot id is in hand (never fabricated).
5. **Candidate set** — OStag's relay router is deterministic with a single
   candidate (the routed envelope's session; for unrouted outcomes, the
   quoted envelope's session or the principal's current session,
   reconstructed read-only). Eligibility flags come from what the router
   actually did — routed ⇒ eligible; rejected for access/terminal reasons ⇒
   ineligible with that reason — never from re-invoking the policy. There is
   no hidden candidate pool to enumerate — this is the honest shape of the
   existing router, not a limitation of the port.
6. **Locality/readiness/capacity are omitted** — OStag has no authoritative
   per-runner topology/readiness/capacity registry yet, so these optional
   fields are never fabricated (the model keeps the upstream vocabularies
   for future use).
7. **Decision-level `reasonCode` vocabulary** (safe, closed set):
   `routed`, `duplicate_event`, `policy_requires_approval`,
   `policy_requires_confirmation`, `snapshot_requested`,
   `proposal_confirmed`, `empty_text`, `quoted_message_not_found`,
   `no_current_session`, `terminal_session`, `stale_decision_version`,
   `decision_expired`, `proposal_invalid`, `proposal_mismatch`,
   `proposal_expired`, `access_denied`, `routing_error` (fallback),
   `schema_mismatch`, `explanation_error` (the derivation itself failed —
   recorded from pure values so the routing outcome is untouched).
   Candidate-level codes: `current_session`,
   `quoted_session`, `duplicate_original_route`, `proposal_target`,
   `access_denied`, `session_terminal`. Rendered views sanitize every
   emitted string including the codes themselves (the model only requires
   them non-empty).
8. **`schema_mismatch`** — if the router ever produces an outcome this
   schema cannot represent without changing eligibility semantics, the
   explainer records a `schema_mismatch` decision and leaves the route
   untouched (handoff: never "fix" the route to satisfy the schema).

## Read-only guarantees & the byte-identity proof

- `RouteExplainer` delegates to the real router first and derives the
  explanation **post-hoc** from the actual outcome — including duplicates,
  where the router returns the ORIGINAL envelope (possibly bound to a
  different session than the principal's current one): `selected` is taken
  from that envelope's binding, with candidate code
  `duplicate_original_route`. The COMPLETE explanation pipeline sits
  inside the best-effort boundary, with the two failure classes declared
  separately: a **derivation** failure (schema, sqlite, anything) degrades
  to an `explanation_error` decision — first with the caller's id/stamp,
  then with a valid epoch stamp if the caller's own timestamp was invalid,
  then pure constants, and as a last resort the explanation is dropped
  entirely; a **recording** failure is silently dropped (`_record_safe`),
  losing only the explanation. In every case the routing result and router
  exceptions pass through untouched. Failed proposal confirmations keep
  the proposal binding's routing context (candidate `proposal_target`,
  real `runId`).
- **Corpus proof**
  (`test_corpus_outputs_identical_with_and_without_explainer`): a scripted
  corpus (plain routing, immediate duplicate, approval-gated text,
  confirmation proposal, quoted decision answer, session switch followed by
  a duplicate replay of the old event, routing to the new session,
  no-session error, empty-text error) runs through a bare service and an
  explainer-wrapped service on two fresh stores; the test asserts the
  COMPLETE `RelayResult` (state, outbound envelope, proposal id, policy
  outcome) and row-identical relay tables (`relay_messages`,
  `relay_sessions`, `relay_current_tasks`, `relay_decisions`,
  `relay_task_proposals`, `relay_platform_messages`, `relay_callbacks`,
  `relay_instance_cursors`). A controller-level test proves the wired
  production path returns identical `FeishuRelayResponse`s and identical
  relay state while recording decisions.
- Determinism: same corpus on two stores yields row-identical
  `routing_decisions` (`test_explanations_are_deterministic`).
- `selected` equals the actual route **by construction** (taken from the
  routed envelope's binding) and is asserted against it in tests.
- The dual-device acceptance fixture still reports
  `status=passed … crossed_routes=0`.

## Persistence, scoping

Migration v24 is additive (`routing_decisions`, PK `decision_id`;
`instance_id` may be `''` for attempts that failed before a session was
found); the migration test seeds v23 data (a completion thread + an
escalation) and asserts it survives untouched. Records are immutable AND
principal-attributed: an identical replay by the same principal is a no-op,
a content mismatch raises `immutable_record`, and a cross-principal id
collision raises `conflict` (never silently absorbed). Views reuse the
established boundary: **personal** = the principal's own routing decisions;
**admin** = all decisions, requires a bound global owner; rendered views
sanitize every emitted string. `get()` is internal/unredacted as in
Phases 3–4.
