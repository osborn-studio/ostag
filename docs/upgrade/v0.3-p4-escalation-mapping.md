## The rule this phase enforces

**An expired escalation never authorizes anything.** Concretely:

1. A late acknowledgement or resolution (`at >= expiresAt`) is **coerced to
   `expired`** — the human's late input is not recorded as attribution, and
   the governance event records `rejectedLateTransition` with the state the
   caller attempted (upstream `expiredDueToDeadline`).
2. Expired escalations map to an inactive `EscalationInput`
   (`active == False`), so the Phase 1 evaluator neither blocks on them nor
   treats them as satisfied approvals.
3. Explicit expiry (`toState=expired`) is only valid at or after the
   deadline; an early expiry attempt raises.

## Declared divergences / native mappings

1. **Actor attribution** — upstream embeds full `ActorIdentity`; OStag uses
   the compact `ActorRef` (`actorId`, `handle?`) already declared in the
   Phase 1 mapping. Replay-idempotency compares `ActorRef.to_dict()`
   equality (upstream compares a stable JSON of the actor).
2. **Timestamps** — strict Phase 3 UTC grammar
   (`YYYY-MM-DDTHH:MM:SS[.ffffff]` + `Z`/`+00:00`); upstream accepts any
   `z.string().datetime()`. All deadline comparisons use parsed instants.
3. **Work-thread existence** — upstream requires a `WorkThread` row; OStag's
   analog is the `completion_threads` table (threads exist once completion
   governance has touched them, and escalation feeds the completion
   evaluator). Opening an escalation for an unknown thread raises
   `not_found`.
4. **`workThreadId`** — carries OStag's `"{instance_id}/{task_id}"` key
   (baseline §6.3); every row is additionally scoped by `instance_id`.
5. **`ActionHint.metadata`** — a free JSON object with unvalidated values,
   matching upstream `z.record(z.unknown())`; declared here because every
   other field in Phase 3/4 models is strictly typed.
6. **`subjectRef`** — required on the stored model (as upstream); OStag
   callers use `"{contract_id}@{contract_version}"` for completion-driven
   escalations by convention (not enforced).
7. **Governance events** — upstream has a dedicated `governanceEvents`
   table; OStag reuses `completion_governance_events` (v21) since the shape
   is identical (`event_type`, `subject_id`, `payload_json`).
8. **Audience → view mapping (handoff §8)** — `requester` and
   `work_item_owner` surface on the **personal** view (own bound instances
   only); `repo_owner`, `operator`, `security` require the **admin** view
   (bound global owner). Rendered views sanitize all free text
   (`sanitize_user_text` + newline flattening), reusing the Phase 2
   boundary. The unredacted `get()`/`list_for_thread()` accessors are
   internal, as in Phase 3.

## Persistence & rollback

Migration v23 is additive-only
(`test_migration_v23_is_additive_from_v22_fixture`). `active_dedupe_key` is
`NULL` once the slot is released; SQLite unique indexes ignore `NULL`s, which
matches upstream's nullable `activeDedupeKey` column semantics. Rollback =
downgrade code; the table is inert to older code.

## Phase 1 integration

`EscalationStore.escalation_inputs(instance_id, work_thread_key)` returns the
`EscalationInput` tuple the Phase 1 evaluator consumes
(`evaluate_completion(..., escalations=...)`): `open`/`acknowledged` +
blocking ⇒ active (thread blocked), everything else — including `expired` —
inactive. No evaluator changes were needed; Phase 1 shipped the input shape.
