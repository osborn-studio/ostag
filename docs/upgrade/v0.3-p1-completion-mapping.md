## Wire contract

Canonical JSON field names, enum values, and invariants are preserved
(camelCase on the wire, `snake_case` Python attributes with serialization
aliases; round-trip covered by `tests/test_completion_models.py`). The
evaluator's roll-up order, digest composition (including the
`waiverValidity` window), authoritative-evidence tie-breaks, and
stale-version semantics follow `evaluate.ts` branch-for-branch
(`tests/test_completion_evaluate.py`).

## Deliberate divergences (native schema, NOT "exact upstream")

1. **`assessedBy` emits `"ostag" | "human"`** (upstream: `"opentag" | "human"`).
   Compat test asserts `"opentag"` is rejected by validation.
2. **Run results simplified** to `{runId, conclusion, recordedAt}` with
   `conclusion ∈ success|failure|cancelled|timed_out|interrupted|needs_human`.
   Upstream wraps a full `OpenTagRunResult`; OStag's evaluator only consumes
   the conclusion, exactly as upstream's evaluator does.
3. **`MaterialActionReceiptFact.actionFamily` is first-class** (upstream reads
   `receipt.metadata["actionFamily"]`). Same selection semantics.
4. **Waiver/assessment actor is `{actorId, handle}`** (upstream
   `ActorIdentity`); waiver reason strings render `handle or actorId`,
   mirroring upstream's `handle ?? providerUserId`.
5. **`EscalationInput` is a minimal evaluator-facing shape**
   (`id/blocking/state/reason/openedAt/resolvedAt`); "active" =
   `blocking && state ∈ {open, acknowledged}` per upstream
   `activeBlockingEscalations`. The full `HumanEscalation` lifecycle arrives
   in Phase 4 and will feed this same input.
6. **`instance_id` dimension added to every persistence row** and
   `work_thread_id := "{instance_id}/{task_id}"` at integration points
   (Phase 0 baseline decision 6.3): scoped reads always join through the
   existing personal/admin authorization boundary; no completion record is
   queryable by task id alone (`tests/test_completion_store.py::test_instance_isolation_no_cross_instance_reads`).
7. **Head tracking table `completion_threads`** replaces upstream
   `workThreads.currentAssessmentId`; seeded by `record_contract` (upstream
   threads pre-exist). Append semantics (dup-by-id, dup-by-input-digest,
   immutability, head CAS → `recorded|duplicate|conflict`, supersession and
   sequence enforcement) match `repository.ts` step-for-step.
8. **Sorting assumption:** ids and ISO-8601 UTC timestamps are ASCII, so
   Python lexicographic order matches upstream `localeCompare` for our data.

## Persistence & rollback (baseline decision 6.5)

- Evaluator is pure (no IO); injected `evaluated_at` everywhere in tests.
- SQLite (`MonitorStore` migration **v21**, additive, `PRAGMA user_version`)
  is the source of truth; a pre-upgrade fixture-open test proves existing
  rows stay readable (`test_migration_v21_is_additive_from_pre_upgrade_fixture`).
- Monitor-disabled mode (runner without `MonitorStore`): unchanged legacy
  behavior + a best-effort `completion_assessed` JSONL mirror of the same
  terminal outcome as an `execution_compat` assessment
  (`ostag/core/runner.py::_mirror_completion_assessment`); a mirror failure
  can never break the reply path (tested).
- Rollback: the five `completion_*` tables are additive and unread by any
  legacy path; dropping them (and the `completion_assessed` mirror events)
  restores the exact pre-P1 surface. `user_version` downgrade requires the
  documented manual `PRAGMA` step, consistent with the store's
  downgrade-refusal policy.

## Legacy-equivalence scope (baseline decision 6.1)

The N=1 equivalence claim covers only the `core/runner.py` terminal-status
path: `record_status` remains untouched and authoritative; the compat
assessment mirrors the same outcome (`satisfied` ⇔ `succeeded`,
`unsatisfied` ⇔ `failed`). Multi-attempt aggregation is deferred to Phase 2
integration.
