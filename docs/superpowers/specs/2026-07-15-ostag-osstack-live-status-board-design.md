# OStag osstack 实时状态看板设计

日期：2026-07-15  
状态：已完成交互设计评审，等待书面规格确认

## 1. 目标

当已授权用户在飞书私聊 OStag 询问“现在 osstack 在干嘛”“目前开发进展怎么样”“有哪些设备和 Agent 正在运行”等状态问题时，OStag 必须立即返回一张手机优先的实时进度看板。

状态查询是只读操作：不创建 Copilot Relay 指令、不写入 relay outbox、不改变 osstack 任务或会话，也不回复“指令已排队”。明确要求继续开发、改变方向或回答决策的消息仍进入现有精确会话队列。

所有员工共用同一个 OStag 飞书应用。系统依据飞书平台验证的 `open_id` 和持久实例绑定，只展示当前用户有权访问的设备、Agent、会话和任务。负责人拥有团队全局只读权限，但私聊默认仍显示自己的设备，并通过负责人专属入口查看团队总览。

## 2. 当前问题与根因

飞书适配器当前按照以下顺序处理消息：

1. `parse_monitor_command` 识别明确的 Work Monitor 命令；
2. `CopilotFeishuController` 处理 Copilot Relay 私聊；
3. 通用 OStag runner 处理剩余消息。

`parse_monitor_command` 能识别“看板”“用看板汇报目前进展”，但无法识别不含“看板”二字的自然语言状态问题，例如“现在 osstack 在干嘛”。该消息因此落入 Copilot Relay，被解释为普通协作指令并返回“指令已排队”。

修复不能只改回复文案。必须在进入 Copilot Relay 之前识别只读状态意图，并生成真实看板，确保查询不会产生任何本地待执行指令。

## 3. 已选择方案

选择“统一实时驾驶舱”方案：

- 全局关键指标回答整体是否在运行、阻塞或等待决策；
- 当前协作会话回答用户正在和哪个 osstack 会话协作；
- 每个会话明确显示设备与 Agent；
- 最近动态和建议回答下一步是否需要用户参与；
- 负责人可从“我的设备”进入“团队总览”；
- 普通员工只能看到本人绑定实例，不生成团队总览入口。

未选择的方案：

- 仅复用历史 Work Monitor 全局看板：会混入无关历史任务，不能清楚回答当前 Copilot 会话状态；
- 仅返回当前 Copilot 会话卡：无法看到其他本人设备，也不能支持负责人团队总览。

## 4. 状态意图路由

新增独立、确定性的状态意图识别器。它在飞书适配器的 Work Monitor/Copilot Relay 分流之前运行，并只接受规范化后的消息文本。

### 4.1 应识别为只读查询

识别包括但不限于以下等价表达：

- `现在 osstack 在干嘛`
- `osstack 正在做什么`
- `目前开发进展怎么样`
- `有哪些设备和 agent 正在运行`
- `给我看工作状态`
- `看板`、`用看板汇报目前进展`

识别器先执行 Unicode NFKC、大小写归一、首尾空白清理，并容忍 `osstack`、`OS Stack` 和常见中文空格形式。规则必须同时要求状态/进展/查看语义，不能因为文本中出现 `osstack` 就把开发指令误判为查询。

### 4.2 应继续作为写入指令

以下消息保持现有 Copilot Relay 行为：

- `继续开发`
- `换成方案 B`
- `先补测试再部署`
- 引用等待决策卡片并回复选择或自由文本答案

### 4.3 混合意图

若一条消息同时包含状态查询和改变工作的要求，例如“告诉我现在进展，然后换成方案 B”，OStag 不猜测也不静默执行：

1. 返回当前只读看板；
2. 明确提示用户把修改指令单独发送；
3. 不创建 relay 指令。

此规则优先保障状态查询不会意外触发开发、部署或其他写操作。

## 5. 身份、设备与权限模型

### 5.1 共享机器人

所有用户私聊同一个 OStag。身份只来自飞书已验证事件中的 `open_id`，不得信任消息正文、按钮负载或用户输入的设备名。

### 5.2 持久实例归属

增加持久化的“飞书用户 ↔ osstack 实例”归属记录，至少包含：

- `instance_id`，稳定设备/Reporter 标识；
- `principal_platform`，本设计为 `feishu`；
- `actor_id`，飞书 `open_id`；
- `display_name`，例如 `Mac mini`，为空时回退到 `instance_id`；
- `created_at`、`revoked_at`；
- 唯一约束：一个有效 `instance_id` 默认只能归属一个普通员工。

一个员工可以绑定多台实例。负责人也应显式绑定自己的实例，以支持“我的设备”默认视图；其全局负责人角色只用于团队总览，不改变默认范围。

### 5.3 私聊角色

现有私聊绑定角色扩展为：

- `admin`：全局负责人，可查看团队总览并管理实例归属；
- `owner`：保留现有兼容语义；
- `member`：普通员工，只能访问本人实例。

旧数据库中现有 `admin`/`owner` 绑定保持原权限，不进行破坏性迁移。员工绑定由管理员通过受控 CLI 建立或撤销；初版不提供员工自助扩大范围的入口。

### 5.4 授权规则

- 员工查询：只读取归属于该 `open_id` 的实例和会话；
- 负责人“我的设备”：只读取负责人显式绑定的实例；
- 负责人“团队总览”：读取所有未撤销实例；
- 切换任务：只列出当前视图范围内允许访问的会话；
- 控制和改变方向：继续使用现有精确会话绑定、灰度范围、审批与回执规则；
- 伪造 `instance_id`、设备名或 Agent 名不能扩大授权范围。

## 6. 数据来源与视图模型

看板只读取中央服务器已有投影，不直接访问员工电脑：

- Work Monitor：实例在线状态、最近心跳、任务状态、进度和项目；
- Copilot Relay：会话标题、`instance_id`、`agent_id`、会话状态、最近摘要、最后更新时间、等待决策和消息回执；
- 身份存储：当前用户允许查看的实例集合和显示名称。

新增平台中立的 `OsstackStatusBoardView`，至少包含：

- 视图范围：`personal` 或 `team`；
- 设备总数、在线数；
- 运行中、等待决策、阻塞、本日完成数量；
- 当前选中会话；
- 最多四个活跃会话摘要；
- 最多三个需要用户处理的事项；
- 数据生成时间和最旧数据更新时间；
- 空状态、离线状态和数据过期标记。

统计和排序为纯函数：等待决策、阻塞、运行中、空闲、完成依次排序；同级按最近更新时间倒序。所有时间在卡片中显示为北京时间，并明确标注。

## 7. 飞书 C 看板

标题：`OStag · osstack 实时进度看板`

### 7.1 信息结构

1. 范围与健康：`我的设备`/`团队总览`、在线数量、整体状态；
2. KPI：运行中、等你决策、阻塞、今日完成；
3. 当前协作会话：标题、设备显示名、`instance_id`、Agent、状态、最近进展、更新时间；
4. 需要你处理：等待决策和阻塞项；
5. OStag 建议：基于当前状态给出一句确定性建议；
6. 页脚：`只读状态查询`、北京时间和数据新鲜度。

### 7.2 按钮

- `刷新看板`：重新读取中央投影并更新卡片，不创建 relay 指令；
- `当前会话`：显示当前选中会话详情；
- `切换任务`：显示授权范围内的会话选择器；
- `团队总览`：仅负责人可见，切换到团队范围；
- 团队视图提供 `我的设备` 返回按钮。

按钮继续使用一次性、身份和目标绑定、带过期时间的 opaque callback ID。按钮负载不得携带可信 `open_id`、`instance_id` 或权限范围。

### 7.3 数据最小化

- 复用现有内容清洗和卡片大小限制；
- 不展示本地文件路径、密钥、完整终端输出或隐藏系统提示；
- 最近摘要按字符数截断；
- 普通员工卡片不包含其他员工实例的数量、名称或存在性信息。

## 8. 异常与空状态

- 未绑定员工：返回“尚未绑定 osstack”卡片和管理员绑定指引；不进入指令队列；
- 没有会话：展示设备在线状态和“当前没有会话”；
- 设备离线：标红离线状态，并显示最后上报的北京时间；
- 中央状态暂不可用：返回稳定的状态服务错误卡；不回退到 Copilot Relay；
- 卡片生成失败：发送经过清洗的只读文本摘要；
- callback 过期或身份不匹配：返回稳定错误提示，不改变视图或任务；
- 数据陈旧：超过既有 offline/degraded 阈值时明确标注，不把最后状态伪装成实时状态。

## 9. 组件边界

### 状态意图识别器

输入文本，输出 `status_query`、`mixed` 或 `none`。无数据库和网络依赖，可独立测试。

### 实例归属存储

只负责创建、撤销和查询飞书用户与实例的持久关系，并维护唯一约束。不得承担卡片渲染或消息路由。

### 状态看板服务

接收经过验证的 Principal、范围和中央存储，执行授权后构建 `OsstackStatusBoardView`。不得发送消息或创建 relay envelope。

### 飞书渲染器

把平台中立视图渲染为飞书卡片，负责转义、截断、按钮和大小限制。不得自行查询数据库。

### 飞书控制器/适配器

负责路由优先级和发送。状态查询必须先于普通 Copilot 指令处理。

## 10. 测试与验收

### 10.1 单元测试

- 中文、英文、大小写、空格和标点的状态查询识别；
- 开发指令和混合意图不被误执行；
- 个人/团队范围统计、排序、空状态和数据陈旧；
- 设备显示名回退、Agent 展示和北京时间；
- 卡片转义、截断、元素数量和编码字节限制；
- callback 一次性、过期、身份和目的地绑定。

### 10.2 权限测试

- 员工 A 只能看到 A 的实例；员工 B 的实例不可见；
- 输入或 callback 伪造 B 的 `instance_id` 仍被拒绝；
- 负责人个人视图不意外展示团队实例；
- 负责人团队视图覆盖全部有效实例；
- 撤销实例归属后立即失去读取和切换权限；
- 旧 `admin`/`owner` 私聊绑定迁移后保持工作。

### 10.3 路由集成测试

- “现在 osstack 在干嘛”返回结构化 C 看板；
- 查询前后 relay outbox 和当前会话版本不变；
- “继续开发”仍生成精确会话 instruction；
- 混合意图只返回看板和拆分提示；
- 未绑定、离线、状态服务错误不会回退到排队回复。

### 10.4 生产验收

1. 备份生产 SQLite 和受保护配置；
2. 迁移现有负责人绑定并把 `ostag-local` 显式归属于负责人；
3. 在负责人飞书私聊发送“现在 osstack 在干嘛”；
4. 验证返回 C 看板、设备和 Agent 正确、relay outbox 无新增；
5. 验证“刷新看板”“当前会话”“切换任务”“团队总览”；
6. 用一名测试员工身份绑定单一测试实例，验证不能看到负责人或其他实例；
7. 验证公开健康检查、容器健康、SQLite 完整性和日志无敏感信息；
8. 通过 osstack Loop Engineering 运行完整测试、lint、生产健康和不可变镜像门禁。

## 11. 部署与回滚

数据库迁移只新增表、角色值和索引，不删除或重写已有记录。部署使用不可变镜像和现有命名持久卷。

回滚时恢复上一镜像；新增表可保留但旧代码不读取。若需要立即停用新入口，使用独立配置开关关闭自然语言状态看板，使明确的原有 `看板` 命令仍可用。回滚不得删除实例归属记录或影响 Copilot Relay 已有消息与回执。

## 12. 完成标准

- 用户私聊询问 osstack 状态时收到 C 看板，不再收到“指令已排队”；
- 看板明确显示设备和 Agent；
- 同一个 OStag 为不同员工返回严格隔离的数据；
- 负责人可在个人视图和团队总览之间切换；
- 所有状态查询与刷新均不改变 osstack 或 Copilot Relay；
- 自动化测试、权限隔离测试、真实飞书灰度和生产健康检查全部通过。
