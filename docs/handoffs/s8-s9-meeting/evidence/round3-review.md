# Opus 5.5 三审：参考标签依据

## 结论：P2 已解决（仅限这个合成工程语料）

四个案例的 gold 现在都能从材料文本加 rubric 直接推出，不再依赖未写明的上下文：

- **c006 → uncertain**：措辞泛化，没有标识，origin 为 null。符合"泛化相同措辞且来源不足"这一条。
- **c008 → distinct**：对象（项目甲/乙）和记录号（R08-A/B）都不同。符合"不同可识别对象"这一条，不再需要假设背景。
- **c013 → duplicate**：同一通知 N13，内容一字不差，没有新断言。origin 不同不影响判定，rubric 也写明重复不证明证人独立。
- **c014 → duplicate**：同一通知 N14，对象（仓库甲）和日期都明确。origin 为 null，但标识足以认定是同一通知。

c008 与 c013、c006 与 c014 这两组对照的区分依据，现在都落在文本里可见的标识和对象上，自洽。

## 剩余的具体问题（都是 P3，不阻塞）

1. **rubric 边界只是隐含的。** c006 与 c014 的 origin 都是 null，判定不同完全靠"文本自带可识别标识，就不算 generic"。rubric 目前没有写明这一点。建议补一句：可识别的通知或记录 ID 加具体对象，可以替代 origin 作为同一性依据；origin 缺失本身不导致 uncertain。
2. **存在捷径风险。** 目前判定可以退化成"ID 字符串相同就是 duplicate，不同就是 distinct"，测不出语义判断。目前还没有这两类反例：
   - 同一 ID 但内容有新增或矛盾（应为 distinct）；
   - 无 ID 但对象和细节完全具体相同（可能应为 duplicate）。

   这不属于本次 P2 范围，可以记为后续语料扩充项。
3. **c013 的对象偏弱。** "成本核对"没有写明是哪个项目，同一性只靠 N13 支撑。可以接受，但如果想和 c014 的强度对齐，可以补一个对象名。

结论依然是 inconclusive：这不是模型收益验收，也不是盲测，holdout 已公开。
